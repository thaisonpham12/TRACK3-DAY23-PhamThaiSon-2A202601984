## 2. Architecture

The system is constructed as a compiled LangGraph `StateGraph` with 11 registered nodes:

- **Graph Nodes (11 total)**:
  1. `intake`: Normalizes raw query text.
  2. `classify`: Uses LLM structured output to classify query into one of 5 routes.
  3. `tool`: Executes external mock tools and handles transient error simulation.
  4. `evaluate`: Evaluates tool execution quality (`success` vs `needs_retry`).
  5. `answer`: Synthesizes grounded final answer from execution context using LLM.
  6. `clarify`: Generates actionable clarification questions for ambiguous/rejected requests.
  7. `risky_action`: Prepares sensitive operations for human-in-the-loop review.
  8. `approval`: Records human approval decisions (`approved=True/False`).
  9. `retry`: Increments retry attempt counter and logs transient failure notes.
  10. `dead_letter`: Handles max retry exhaustion and sets escalation response.
  11. `finalize`: Emits standardized audit event before termination.

- **Fixed Edges (8 total)**:
  - `START` → `intake` → `classify`
  - `tool` → `evaluate`
  - `risky_action` → `approval`
  - `answer` → `finalize`
  - `clarify` → `finalize`
  - `dead_letter` → `finalize`
  - `finalize` → `END`

- **Conditional Edges (4 total)**:
  - `route_after_classify`: `simple` → `answer`, `tool` → `tool`, `missing_info` → `clarify`,
    `risky` → `risky_action`, `error` → `retry`.
  - `route_after_evaluate`: `needs_retry` → `retry`, other → `answer`.
  - `route_after_retry`: `attempt < max_attempts` → `tool`,
    `attempt >= max_attempts` → `dead_letter`.
  - `route_after_approval`: `approved is True` → `tool`, `rejected/missing` → `clarify`.

- **Termination**: Every path converges at `finalize` → `END` to guarantee audit trail emission.

## 5. Failure analysis

1. **Retry or tool failure (Transient Error → Bounded Retry → Dead-Letter)**:
   - *Failure origin*: External tool API timeout or network failure in `tool_node`.
   - *Detection signal*: `evaluate_node` detects `ERROR` in `tool_results[-1]` and sets
     `evaluation_result = "needs_retry"`.
   - *Graph progression*: `route_after_evaluate` routes to `retry_or_fallback_node`, which
     increments `attempt` by 1 and appends error history.
   - *Termination guarantee*: `route_after_retry` checks `attempt < max_attempts`. When attempts
     reach `max_attempts`, graph routes to `dead_letter_node` → `finalize` → `END`.
   - *Residual risk*: If transient errors persist across all attempts, user receives escalation
     notice without automated resolution.

2. **Risky action without approval (Side-Effect Quarantine & Human Gate)**:
   - *Failure origin*: High-risk/destructive request (e.g., account deletion, refund).
   - *Detection signal*: `classify_node` identifies intent as `risky` and sets `risk_level="high"`.
   - *Graph progression*: Graph routes to `risky_action_node` to format `proposed_action` without
     executing tools, then reaches `approval_node`.
   - *Containment & Termination*: If rejected, `route_after_approval` routes to
     `ask_clarification_node` → `finalize` → `END`. Zero tool side-effects occur.
   - *Residual risk*: Reviewer fatigue or misconfigured policy in automated reviewer extensions.
